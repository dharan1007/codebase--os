01 / Runtime

The model proposes.
The runtime decides.

Codebase OS is designed so a language model is one component in a controlled engineering loop—not the authority that decides whether its own work succeeded.

01

Repository graph before generation

Imports, calls, symbols, API contracts and persisted file analysis give planning a structural view of the codebase before a change is attempted.

02

Transactional change history

File mutations are context-validated, recorded durably, and compensated if persistence fails. Rollback refuses to overwrite work that changed after the transaction.

−direct filesystem write
+validated patch + durable record
+conflict-aware rollback
03

Independent verification

The agent cannot make a mutation and simply declare success. The runtime discovers project gates—types, lint, tests, builds and supported language checks—and rejects completion when evidence fails.

02 / Architecture

More runtime.
Less prompt theater.

Capabilities are built as inspectable subsystems with deterministic boundaries around retrieval, planning, mutation, verification and recovery.

A

Hybrid retrieval

Lexical search remains available without embeddings; vector retrieval adds semantic ranking when the provider supports it.

LEXICAL + VECTOR
B

Cross-layer contracts

Scans frontend API calls, API endpoints, Prisma schemas and SQL table definitions to surface contract drift across layers.

API + SCHEMA
C

Provider resilience

OpenAI, Anthropic, Gemini, OpenRouter and Ollama can participate in bounded routing with explicit outage and quota failure states.

FAILOVER
D

Engineering memory

SQLite-backed checkpoints, changes and recurring failures preserve evidence across sessions without relying on chat history alone.

DURABLE STATE
E

Sandboxed execution

Shell work runs in an isolated execution path with bounded resources and credential-aware project mounts.

CONTROLLED TOOLS
F

Risk-aware mutation

Change risk uses file semantics, content patterns, dependency centrality, change size and observed agent context before apply.

03 / Security

Assume the repository can be hostile.

Repository tools enforce root containment, realpath checks and sensitive-path policy. Native AI file reads deny common secret-bearing files instead of trusting the model to avoid them.
